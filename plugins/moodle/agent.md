## Moodle

- Moodle code lives in `app/`. In Moodle 5.1 and later, web code and plugins live in `app/public/`, while `app/admin/cli/` stays at the root. Moodle data lives in `data/` (the `moodledata` directory). Never put code in `data/` or serve it.
- Run admin CLI scripts with `dev exec php app/admin/cli/<script>.php`. Common ones: `purge_caches.php`, `upgrade.php --non-interactive`, `cfg.php --name=<setting>`, `cron.php`.
- Purge caches after changing code, themes or language strings: `dev exec php app/admin/cli/purge_caches.php`.
- Take a `dev snapshot` before `upgrade.php` or any plugin install or removal.
- Cron runs every 60 seconds from `dev.schedule`. Check it with `dev schedule`.
- `app/config.php` is generated by `dev`. Keep the database and `dataroot` settings unchanged. The block between `// >>> dev test` and `// <<< dev test` belongs to `dev test`.

### Moodle tests

- `dev test phpunit [args]` runs PHPUnit from `app/`, so paths are relative to `app/`. Example: `dev test phpunit --filter=my_test` or `dev test phpunit public/local/myplugin/tests/my_test.php`. Unit tests live in the plugin's `tests/` directory, named `*_test.php`.
- `dev test behat [args]` runs Behat acceptance tests in the dev Chrome against {{TEST_URL}}. Example: `dev test behat --tags=@local_myplugin`. Features live in the plugin's `tests/behat/*.feature` and should carry the plugin tag (for example `@local_myplugin`) and `@javascript` when they need a real browser.
- After a version bump, a new plugin, or new Behat steps, run `dev test init phpunit` or `dev test init behat` before the suite.

### Moodle documentation

- `/websites/moodledev_io` — Moodle Developer Resources (moodledev.io): plugin types, core APIs, the `version.php` and `db/` files, Output API, Mustache templates, AMD modules, Behat and PHPUnit.
- `/moodle/devdocs` — the source of the same documentation, useful when the first ID has no answer.
- `/moodle/moodle` — Moodle source code, for exact function and class signatures.
- Moodle APIs change between releases. Check the version above and look for deprecation notes before you use an API.
